## 必须共同约定的事项

### 1. 唯一整合工程和资源分配（A/B/C）

整合时只保留一个顶层和一份统一 CST/SDC。B 当前使用 T11/P11/T12，独立测试版本为 motor_control_v1_bank2_3pin；联合程序使用其 integration 正式三脚执行链。main@623c288 与旧实验目录不是新引脚依据。旧四脚约束必须移除，摄像头及占用这三脚的外设不连接；C 须核对联合工程无重复占用。详见 [最新引脚说明](B_PINOUT_2026-10-08.md)。

实际发现 N16 冲突后，用户明确选择调整 B：A 保留 LED2/N16，B 就绪灯改为 LED3/N14，运行灯 LED4/L14、锁定灯 LED5/L16。独立工程 motor_protection_jog_ab_led3 已完成构建、实际引脚报告检查、用户下载后的锁定/清除检查，以及实际点动“转动后停下，CV”；该记录属于旧四脚版本，本次三脚接线以新表为准。此前“把 N16 留给 B、取消 A 编码器灯”的建议被此用户选择取代。UART TX M11 仍应只有一个统一发送模块驱动。B 新三脚版不再占用 T9；板载 RGB、MIC 等其他资源仍由联合工程统一分配。

按键目前 S0 复位、S1 清锁/启动、S2 逻辑急停、S3 模拟故障；合板需统一职责，不能沿用旧 B 的 S3 换向解释。C 若加显示屏或其他外设，要先登记新增引脚。A/C/B 同一 FPGA 内部的四状态和 control_u 走内部连线，不需另分配外部 GPIO。

### 2. A→C 数据单位与版本（A/C）

实际存在两套源代码：gowin_project/inverted_pendulum/src 为已验证的整数 mrad/mrad/s、978 换算、三点 ADC 标定；rtl/top.v 引用的 rtl/sensor/sensor_math.v 则是 Q16.16 rad/rad/s，并保留按 1040 计数的系数。两个 .gprj 指向不同顶层来源，不能按文件名相同而混合。

建议采用与用户交接一致的已验证 A 工程；C 明确状态排列、整数毫弧度到其控制算法单位的换算，以及增益的定点格式。A 的单位本身已确定，需确认的是 C 接收时使用同一规则。

### 3. 采样、状态快照与控制周期（A/C，B知悉）

用户已经确认 C 正常每 20 ms 产生一次 control_valid，不再询问。此前检出的 C rtl/control_tick.v 默认 1000 Hz（1 ms），集成时需核对实际工程采用已约定的 20 ms；A 两路速度更新 20 ms、ADC 128 SPS，四状态快照与 state_valid 仍需统一。B 的 1 kHz 是 PWM 载波频率。

### 4. C→B control_u 接口与执行模式（B/C）

已确认：signed[15:0] control_u，单位 0.1% PWM，范围 -300～+300；每 20 ms 的 control_valid 为 1 个 27 MHz 时钟周期；motor_enable=0 必须停止。补充约定采用 abs(control_u)/10 整数截断、100 ms 无有效更新停止，fault/estop/protection_locked 优先。

当前正式 motor_control_u_chain_3pin 通过 control_u_adapter 连接原 motor_protected，核心无 200 ms 运行上限；独立 dock_motor_control_v1 顶层仍模拟 C 做正向 10%/200 ms 点动。原 motor_protected 的 command/arm/duty_pct 端口不能直接接 C 的三个协议输入。三脚版三项仿真及构建通过，尚未上板；此前“符合预期，CV”是旧四脚点动记录。

须随包交接的 B 规则：超时锁定且人工清除；禁用清掉旧命令，再使能须新的 control_valid；小于 1% 的有效占空比请求按停止处理。**1 秒停止/换向等待仍保留**，进入平衡控制前必须共同确定并验证新的换向策略。机械正方向尚未定义。详细约定见 [C→B V1.0](CONTROL_INTERFACE_V1_2026-09-27.md)。

### 5. 方向和标定统一（A/B/C）

以明确观察视角约定 theta 正方向、alpha 正方向以及 control_u>0 时的实际转向，并用传感器与小幅电机动作联合核验。A 文档已写 CCW 为 theta 正、向右为 alpha 正，不必重问文字定义。978 保留暂定，最终整圈实测后同步更新 C 模型/换算；B 约 8% 启动阈值仅适用于此前测试条件，死区补偿由 B 或 C 一处实现，不能两边重复叠加。

### 6. 标定、启动、故障和急停责任（A/B/C）

A calibration.v 在复位后 0.5 s 自动捕获零点；需确保有效数据、正确姿态、并在电机启动前完成。C 的现有 control_fsm.v 仅按计时从 IDLE→CALIBRATION→READY→RUN，没有接入真实标定完成、传感器故障或人工启动。当前只是状态演示，不能因此授权电机自动启动。

建议职责：A 发布有效状态、标定完成及传感器故障；C 管理允许进入闭环和机构角度/速度范围；B 在最终输出处执行停机与锁定。共同确定数据过期时限、控制命令丢失处理、旋转臂可动范围/线缆缠绕限制、正常停机方式、故障清除必须人工重新启动。S2 是逻辑急停，独立硬件断电急停尚未实现，需明确负责人和验收方式。

### 7. 共同电源与电平方案（A/B，C知悉）

确认最终合板电源分工、公共地和逻辑电源来源，避免各自调试电源正极直接并联。用户已确认 A 与 B 各用一块相同的 CJMCU-245 / SN74LVC4245A，不共用；此项已从待确认事项删除。B 的板执行 3.3→5 V，A 的板执行 5→3.3 V，两块分别配置相反方向。

ADS 芯片 VDD≈5 V 与 3.3 V 上拉已明确。需由 A 确认板内是否存在电平转换，若总线直接连接芯片，则需按高电平保证门限处理兼容性；不再要求重复测已确认电压或上拉阻值。
