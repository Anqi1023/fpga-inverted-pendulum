# A 组彻底完成路线与状态清单

更新日期：2026-09-17。目标分支：`feature/sensor`。

本清单按固定顺序执行：

`测量 mm/rev -> 接线/管脚 -> 完善并综合代码 -> 实机标定 -> 验证并交付 C 组`

状态含义：

- **已确认**：仓库、官方资料或实物照片已有充分依据。
- **Codex 完成**：可在仓库内完成并验证，不需要先做新的实物测量。
- **用户操作**：必须在实物上接线、测量、下载或移动机构，结果回传后才能继续定值。
- **双方确认**：需要 A/C 对接口定义达成一致。

| rst_n | T10 | 板载按键 | 管脚已确认；有效极性需实机确认 |

摆杆不再占用 `angle_enc_a/angle_enc_b`；角度来自 ADS1115。

### 2.2 编码器安全接线

计划链路：编码器 5 V A/B -> CJMCU-245 B1/B2 -> A1/A2 -> FPGA T6/P6。

| 接线 | 结论 |
|---|---|
| CJMCU VCA | 接 Dock 3.3 V |
| CJMCU VCB | 接编码器 5 V |
| CJMCU GND | 与编码器、Dock 共地 |
| DIR | 接低电平，方向 B -> A |
| OE | 低有效；测试时接地使能，正式设计建议确保上电期间不会悬空 |
| 编码器 B1/B2 | A 相/B 相 |
| FPGA A1/A2 | T6/P6 |

待用户实测：编码器供电 5 V 后，A/B 对编码器 GND 的高、低电平；静止与缓慢转动都测。预期约 0/5 V，但没有测量前不作为事实。

### 2.3 ADS1115 与 WDD35D4

计划模拟链路：WDD35D4 输出 -> ADS1115 AIN0；WDD35D4 中间端 3.3 V；另一端 GND；三者共地。

计划数字链路：ADS1115 SCL -> T8，SDA -> P8，ADDR -> GND（7-bit 地址 0x48），A/R 暂不接。

为了让 I2C 电平天然兼容，首选让 ADS1115 模块整体使用 3.3 V，前提是模块实测确认 `+5V` 端在 3.3 V 输入下能正常工作且 SDA/SCL 上拉为 3.3 V。

以下必须由用户用万用表确认，先不接 FPGA：

1. 模块 `+5V` 接 3.3 V、GND 共地，测 ADS1115 芯片 VDD 是否约 3.3 V。
2. 测空闲 SDA、SCL 对 GND 是否约 3.3 V。
3. 断电测 SDA/SCL 与 `+5V` 端之间是否有上拉电阻通路；记录阻值。
4. 若模块只能 5 V 供电或 SDA/SCL 被上拉至 5 V，必须增加适合开漏 I2C 的双向电平转换；CJMCU-245 不能作为自动双向 I2C 转换器。
5. WDD35D4 接 3.3 V 后，测输出最小、竖直向上和最大位置电压，必须保持在 0-3.3 V 范围内再接 AIN0。

ADS1115 芯片本身支持 2.0-5.5 V VDD；AINx 推荐范围是 GND 到 VDD。具体模块的上拉和电源布线不能只凭芯片手册推定。

### 2.4 尚待消除的管脚冲突

用户提供的最终版 PDF 将 PMOD0 第四个管脚写为 R6，而实物背面照片及此前官方原理图核对记录为 R8。当前 A 组只使用 T6/P6/T8/P8，避开该争议脚，因此不阻挡 A 组接线和 CST。文档仍需更正，方法是用户用万用表通断档核对该焊盘到核心板球号，或提供更高清丝印近照。

### 2.5 由 Codex 完成的文件

在上述电平测量通过后：

- 创建 A 组 Gowin 工程 `.gprj`。
- 创建顶层模块和 `.cst`：H11、T10、T6、P6、T8、P8。
- 创建 27 MHz 的 `.sdc`（37.037 ns）。
- 将 I2C SDA 声明为 `inout` 开漏接口，不输出高电平。
- 运行 Gowin 综合并保存结果记录。

完成标志：CST/SDC 与顶层一致，综合通过，接线电平实测安全。

## 3. 完善并综合 A 模块 RTL

### 3.1 当前仓库已有且已仿真通过

| 模块 | 状态 | 说明 |
|---|---|---|
| quadrature_decoder | 可复用 | 两级同步、A/B 四倍频、正反计数、非法跳变检测 |
| velocity_estimator | 可复用/需改单位 | 当前输出是每采样窗口变化量，尚不是 mm/s 或角度/s |
| 相关 Testbench | 已通过 | Icarus 自检通过；用户反馈 ModelSim GUI 通过 |

### 3.2 当前实现不符合实物、必须修改

`sensor_state.v` 当前把 angle 当作第二路 A/B 编码器，且 position/angle 都是原始 count；没有 ADS1115 I2C、物理单位换算、滤波或实物超时。因此不能作为最终 A 模块综合交付。

### 3.3 由 Codex 实现

1. ADS1115 I2C 主机：启动、配置 AIN0 单端、读取转换寄存器、ACK/NACK 与超时检测。
2. ADS1115 配置参数化：地址 0x48、PGA、数据率、单次/连续模式。
3. ADC 码滤波：先使用小窗口整数滤波；窗口大小参数化。
4. `angle`：用 `adc_filtered - angle_zero_adc` 表示标定后的有符号量，再按标定系数转换为统一定点角度。
5. `angle_vel`：固定周期差分，输出统一时间单位。
6. 小车编码器：四倍频并按 1040 count/rev 解释。
7. `position`：按实测 mm/rev 转换为定点 mm。
8. `position_vel`：按固定周期转换为定点 mm/s。
9. `sensor_valid`：ADC 初始化/ACK/超时/范围、编码器非法跳变计数、标定状态共同决定。
10. 固定更新周期：初版建议 10 ms（100 Hz），最终需 C 组确认；27 MHz 下为 270000 个时钟周期。
11. 建立新的自检 Testbench，模拟 ADS1115 I2C 从机、静止/运动、NACK、超时和越界。
12. Gowin 综合、时序约束和报告归档。

### 3.4 必须双方确认的数字接口

在最终锁定前，A/C 需要确认：

- angle 单位和定点格式（建议统一为毫弧度或 Q 格式，需 C 确认）。
- angle_vel 单位（建议毫弧度/秒或同一 Q 格式每秒）。
- position 单位（建议 0.001 mm 或 Q 格式，避免整数 mm 分辨率不足）。
- position_vel 单位（建议 mm/s 的定点格式）。
- 位宽（当前候选 signed 32 bit）。
- 更新周期（当前候选 10 ms / 100 Hz）。
- 正方向、有效脉冲/持续电平定义和复位行为。

## 4. 下载 FPGA、零点与方向标定

以下必须由用户在实物上执行，Codex 根据结果修改参数：

1. 编译/下载 A 组测试 bitstream，确认 T10 复位极性。
2. 摆杆竖直向上并保持静止，记录至少 100 个 ADS1115 原始值；均值作为 `angle_zero_adc`，同时记录抖动范围。
3. 将摆杆转到两个已知角度（建议使用量角器，至少正负各一点），记录 ADC 均值，求 ADC-count/rad 或 ADC-count/degree；只测零点不足以得到角度比例。
4. 确定摆杆向哪边为正；若相反，通过参数翻转符号。
5. 小车放在规定位置并复位/置零，定义 `position = 0`。
6. 左右推动小车，记录 count 符号；若相反，交换 A/B 或通过参数翻转符号。
7. 用尺验证多个距离点，不只验证一个 mm/rev；记录误差。
8. 静止记录噪声，决定滤波窗口和速度死区。

完成标志：五个输出不再是原始 ADC/count，具备已记录的零点、比例、单位和方向。

## 5. 实物验证与 C 组对接

| 验收项 | 用户操作 | 判定 |
|---|---|---|
| angle | 慢速转动摆杆至多个已知角度 | 符号和数值与量角器一致 |
| angle_vel | 快慢、正反转摆杆 | 方向正确，快转绝对值更大，静止接近 0 |
| position | 左右移动多个已知距离 | 符号正确，毫米输出在允许误差内 |
| position_vel | 快慢、正反推动小车 | 方向正确，快推绝对值更大，静止接近 0 |
| sensor_valid | 正常、断开 ADS1115、制造 I2C NACK/超时 | 正常为 1，异常在规定时间内变 0 |
| 编码器异常 | 断开 A/B 或制造非法跳变 | 能检测的异常变无效；需注明静止断线无法仅靠 A/B 必然检测 |
| 长时间运行 | 保持上电并反复运动 | 无计数跳变、卡死或 I2C 锁死 |

C 组最终签收内容：五个信号的端口、位宽、定点格式、单位、更新周期、正方向、零点、有效时序和异常恢复方式。

## 6. 现在需要用户依次完成的操作

不要同时上电接线。按下面顺序把结果发回：

1. 测量并记录 `mm/rev`，最好 5-10 圈取平均；同时记录运动方向。
2. 有万用表时，测编码器 A/B 的高低电平和输出轴每圈实际 count。
3. ADS1115 先只接 3.3 V/GND，不接 FPGA，测芯片 VDD、SDA、SCL 空闲电压和上拉阻值。
4. WDD35D4 单独以 3.3 V 供电，测最小、竖直向上、最大位置的输出电压。
5. 焊接并检查 CJMCU-245 排针；不要靠松插排针接触。
6. 等 Codex 提交最终接线表、CST、RTL 和 Gowin 综合结果后，再按表接到 FPGA。
7. 下载测试工程，按第 4、5 节完成标定和验收。

当前最先需要回传的数据：`mm/rev`。如果手边已有万用表，可同时完成第 2-4 项。
